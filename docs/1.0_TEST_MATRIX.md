# BloomOS 1.0 Test Matrix

Status values are `not-run`, `partial`, `partial-remote`, `pass`, `fail`,
`blocked-physical`, or `n/a`. Evidence must identify build SHA,
device/revision, firmware, date, operator, and artifact. `partial` records a
bounded subset of a physical task; `partial-remote` records only remotely
observable properties and never substitutes for physical UX review.

## Automated release gates

| Area | Required evidence |
|---|---|
| Formatting/static analysis | All workflow checks pass |
| Native code | Unit tests and ASan; UBSan where supported |
| Shell boundaries | BusyBox-oriented Bats integration suite |
| Build | Pinned cross-build and reproducibility metadata |
| Packaging | FAT validation, payload manifest, signatures, provenance policy |
| Migration | Fresh, realistic, repeated, malformed, interrupted fixtures |
| UI | 640x480 and 752x560 navigation/layout/golden fixtures |
| Library | 0, 1, 10, 1k, and 10k games; duplicates and malformed data |
| Parsers | Theme, JSON, paths, images, and schema migration fuzz/property tests |
| Performance | Input/render timings, 30-minute shell soak, 500 open/back cycles |
| Privacy | Allowlisted health/support export contains no private data |

## Task-based UX certification

Every task is exercised at 640x480 and 752x560 with automated focus/state
fixtures before physical review. Shoulder events are injected alongside every
surface test and must not alter Bloom navigation state.

| Surface | Required task evidence |
|---|---|
| Root | Continue focus/resume; rail reaches five destinations; child B restores root focus; root B is safe; MENU/START semantics; shoulders no-op |
| Games | Left/Right non-empty systems; independent per-system selection; accelerated Up/Down; A/X/Y/SELECT/B; shoulders no-op |
| Favorites/Recent | Direct root access; shared list; helpful empty states; confirmed context-only recent deletion |
| Settings | One sectioned surface; inline values; capability filtering; one-layer details; hidden Developer section; no shoulder paging |
| Quick Settings | START from core surfaces; immediate brightness/volume/mute; capability-gated Wi-Fi; readable battery; B/START close |
| GameSwitcher | MENU open/toggle; Left/Right select; A resume; X actions; START Quick Settings; B Home; no inherited brightness/view/delete/shoulder behavior |
| Apps/Tweaks | Every app disposition recorded; normal configuration requires no Tweaks; supervised launch remains bounded |
| Search/actions | Shared local search/filter and flat action/detail patterns; no render-path network or hashing |
| First run | One welcome surface; local game count; fixed settings reconciliation before completion; interrupted/malformed/symlinked marker retries; B no-op; MENU/START global; Safe Mode bypass |
| Safe Mode | Interrupted/failed starts latch after the bounded threshold; auto-resume is suppressed; one flat recovery list exposes Games, health refresh, support export, confirmed signed rollback, confirmed Settings reset, and explicit normal restart; reset preserves an exact private backup and leaves games/saves/states/library/history/credentials untouched; RA session work is forced off; B and shoulders cannot leave the recovery root |

## Exit criteria

No stable tag is permitted while an automated gate fails, a P0/P1 remains open,
or a required maintainer-device row is `not-run`. External V1/V3/V4 evidence may
be `blocked-physical`, but stable support claims must then exclude the unproven
revision rather than infer it from V2.
