# BloomOS 1.0 Test Matrix

Status values are `not-run`, `partial`, `partial-remote`, `pass`, `fail`,
`blocked-physical`, or `n/a`. Evidence must identify build SHA,
device/revision, firmware, date, operator, and artifact. `partial` records a
bounded subset of a physical task; `partial-remote` records only remotely
observable properties and never substitutes for physical UX review.

## Automated release gates

| Area | Required evidence |
|---|---|
| Formatting/static analysis | All workflow checks pass |
| Native code | Unit tests and ASan; UBSan where supported |
| Shell boundaries | BusyBox-oriented Bats integration suite |
| Build | Pinned cross-build and reproducibility metadata |
| Packaging | FAT validation, payload manifest, signatures, provenance policy |
| Migration | Fresh, realistic, repeated, malformed, interrupted fixtures |
| Runtime default | Bloom Shell without an enable flag; failures retry to Safe Mode; MainUI requires Developer Mode plus explicit recovery flag |
| UI | 640x480 and 752x560 navigation/layout/golden fixtures |
| Library | 0, 1, 10, 1k, and 10k games; duplicates and malformed data |
| Parsers | Theme, JSON, paths, images, and schema migration fuzz/property tests |
| Performance | Input/render timings, 30-minute shell soak, 500 open/back cycles |
| Privacy | Allowlisted health/support export contains no private data |

## Task-based UX certification

Every task is exercised at 640x480 and 752x560 with automated focus/state
fixtures before physical review. L1/R1 may page only long vertical lists; L2/R2
and all shoulder presses on roots, systems, values, and dialogs must leave Bloom
navigation state unchanged.

| Surface | Required task evidence |
|---|---|
| Root | Continue focus/resume; rail reaches five destinations; child B restores root focus; root B is safe; MENU/START semantics; shoulders no-op |
| Games | Left/Right non-empty systems; independent per-system selection; accelerated Up/Down; optional overlapping L1/R1 list paging; A/X/Y/SELECT/B; L2/R2 no-op |
| Favorites/Recent | Direct root access; shared list; helpful empty states; confirmed context-only recent deletion |
| Settings | One sectioned surface; inline values; capability filtering; one-layer details; hidden Developer section; optional overlapping L1/R1 list paging |
| Quick Settings | START from core surfaces; immediate brightness/volume/mute; capability-gated Wi-Fi; readable battery; B/START close |
| Network services | SSH requires a valid public key; SFTP is independently gated through SSH; Samba uses the bounded compatibility boundary; toggles persist and fail closed on unsupported hardware |
| GameSwitcher | MENU open/toggle; Left/Right select; A resume; X actions; START Quick Settings; B Home; no inherited brightness/view/delete/shoulder behavior |
| Apps/Tweaks | Every app disposition recorded; normal configuration requires no Tweaks; supervised launch remains bounded |
| Search/actions | Shared local search/filter and flat action/detail patterns; no render-path network or hashing |
| First run | One welcome surface; local game count; fixed settings reconciliation before completion; interrupted/malformed/symlinked marker retries; B no-op; MENU/START global; Safe Mode bypass |
| Safe Mode | Interrupted/failed starts latch after the bounded threshold; auto-resume is suppressed; one flat recovery list exposes Games, health refresh, support export, confirmed signed rollback, confirmed Settings reset, and explicit normal restart; reset preserves an exact private backup and leaves games/saves/states/library/history/credentials untouched; RA session work is forced off; B and shoulders cannot leave the recovery root |

The signed Plus UX-convergence evidence is recorded in
[`validation/shell/plus-ux-convergence-20260822.json`](validation/shell/plus-ux-convergence-20260822.json).
It proves exact sampled framebuffer state, injected input transitions, process,
memory, file, and health properties. It does not prove physical-panel behavior,
tactile controls, audio, semantic saves, or successful state restoration.

The signed default-shell activation is recorded in
[`validation/shell/plus-default-shell-20260822.json`](validation/shell/plus-default-shell-20260822.json).
It proves that the Plus booted Bloom Shell without consulting the legacy opt-in
marker, kept MainUI absent without the explicit two-marker Developer fallback,
completed the recoverable first-run surface, reached the five-destination root,
and promoted the exact candidate to known-good with aggregate health green. It
is remote framebuffer/process evidence, not a physical UX pass or the complete
boot/launch/power/recovery certification required for stable release.

The signed real-game and canonical-recents evidence is recorded in
[`validation/shell/plus-session-recents-20260822.json`](validation/shell/plus-session-recents-20260822.json).
It proves a Bloom Shell GB launch reached a live RetroArch process and RUNNING
Bloom session, recorded the canonical GameID without blocking play, populated
GameSwitcher, survived a clean stop/return, and focused Continue Playing on the
returned root. Synthetic input could not cross RetroArch/GameSwitcher input
ownership, so physical MENU, X, START, controls, audio, SRAM, and save states
remain `blocked-physical` rather than inferred from the remote evidence.

The signed representative-game soak is recorded in
[`validation/shell/plus-game-soak-20260822.json`](validation/shell/plus-game-soak-20260822.json).
Across 61 samples at 30-second intervals, one RetroArch PID stayed RUNNING with
RSS exactly 10,804 KiB, VmSize exactly 56,616 KiB, and 13 file descriptors.
Cleanup completed the scoped save flush, returned the exact Continue frame, and
left aggregate health green. Physical latency and gameplay semantics remain
outside this remote performance evidence.

## Exit criteria

No stable tag is permitted while an automated gate fails, a P0/P1 remains open,
or a required maintainer-device row is `not-run`. External V1/V3/V4 evidence may
be `blocked-physical`, but stable support claims must then exclude the unproven
revision rather than infer it from V2.
